> 配套文档：《MoNote 软件设计文档》v1.0（`../../exp02/docs/01-软件设计文档.md`）

> 测试报告：`测试报告.md`

## 1. 实现总览

| 项 | 实现 |
| --- | --- |
| 应用壳 | Tauri 2.12（Rust 2021，进程内 WebView2 + 核心） |
| 前端 | 原生 HTML/CSS/ES Module（无框架、无打包器），`frontend/` 直接由 Tauri 作为 `frontendDist` 加载 |
| 前端第三方库 | marked（Markdown）、KaTeX（公式）、highlight.js（代码高亮）——已本地化到 `frontend/vendor/`，离线可用 |
| 核心 | `src-tauri/src/core/` 九个模块：vault / links / index / io / backup / sync / config / notify / update |
| 索引 | SQLite（rusqlite bundled，FTS5），WAL 模式，派生可重建 |
| 凭据 | `keyring` crate → Windows Credential Manager（服务名 `MoNote.WebDAV`） |
| 网络出口 | 仅 WebDAV（同步）与更新清单检查两处（NFR-108） |

源码规模：Rust 约 8.5k 行（含单元测试），前端约 3.5k 行，测试约 150 个断言场景。

## 3. 关键实现说明

### 3.1 崩溃安全写（F-01 / NFR-105 / DD-7）
`Vault::write_atomic`：同目录写 `<name>.tmp-<pid>-<rand>` → `write_all` → `sync_all` → `rename` 原子替换；
启动时 `cleanup_temp_files()` 清理残留 `*.tmp-*`。前端 SaveScheduler 保证同一时刻至多一个写请求在途，
保存失败保留编辑缓冲并提示，30s 重试由前端兜底。

### 3.2 修订号与并发（F-01）
`state.rs` 维护 `path → rev` 内存表；`vault.write{expectRev}` 不匹配返回 2004（`ERR_REV_CONFLICT`）。
切换库时清空修订表；重命名/删除同步迁移/删除。

### 3.3 索引一致性（7.2 / X-2）
`notes.hash` 为唯一裁决字段；单笔记重索引 = 单事务（notes + notes_fts + links + tags）。
启动时 `reconcile_index()`：目录扫描 vs `notes` 表按 mtime 差异重索引、孤儿条目删除；
`index.rebuild` 后台全量重建，进度经 `index:progress` 事件推送，失败自动降级并保留旧索引句柄。
索引损坏（`database disk image malformed` 等）时把 db 文件改名为 `.corrupt-<ts>.db` 后重建；
重建失败则整个应用进入"逐文件扫描"降级检索（`degraded=true`，FR-302 异常路径）。

### 3.4 中文全文检索（DD-4 的落地方式）
SQLite `unicode61` 会把连续 CJK 字符当作一个 token，无法"按字"子串匹配。实现采用
**索引前 CJK 字符空格分隔 + 查询侧同构转换**：`虚拟内存` → `虚 拟 内 存`，查询生成 FTS5 短语
`"虚 拟 内 存"`，从而实现"按字命中 + 子串可命中"。英文/数字按词匹配。`tag:` 前缀改写为 JOIN tags，
多关键词 AND、英文双引号精确短语由 `parse_query()` 解析（纯函数，可单测）。

### 3.5 外部改动检测（F-04 / FR-506）
`watcher.rs` 使用 `notify` 递归监听库根；300ms 去抖后逐路径处理：
1. 本应用写回：`self_writes[path] == content_hash` → 丢弃（ExternalGuard 白名单）；
2. 外部 create/modify：读文件 → hash → 重索引 → `notes:external` 事件（≤5s 收敛）；
3. 外部 delete：索引软删；4. 附件变更：`vault:changed` 刷新树。
watcher 不可用时降级为启动全量对账（30s 轮询未实现，记录为偏差）。

### 3.6 回收站（FR-205 / C-3）
`.trash/meta.json` 逐条记录 `{id,path,deletedAt,stored,isDir,size}`；文件实际存放于 `.trash/<id>__<name>`。
还原时目标冲突自动 `<原名>-还原-<时间戳>`；启动时 `purge_expired_trash()` 清除 >30 天条目；
meta.json 损坏时改名隔离并重建空表（不删除用户文件）。

### 3.7 备份与整库导出（F-06 / FR-402/403）
`zip_snapshot()` 递归打包库根，排除 `.monote/` 与目标 zip 自身，包含 `.trash/`（含 meta.json）。
备份文件名 `monote-backup-YYYYMMDD-HHmmss.zip`，`rotate()` 按 mtime 保留最近 keep 份；
启动后 5s 检查距上次 >24h 则自动备份，失败进通知中心（FR-502/FR-504）。

### 3.8 导入编码与容错（F-07）
`decode_text()`：BOM → UTF-8 严格校验 → GB18030 回退；`is_binary()` 拦截 NUL/二进制；
逐文件处理、单文件失败只进报告不中断批次；路径冲突 `<名>-导入副本-<ts>`；写入经 Vault。

### 3.9 WebDAV 同步（F-05 / FR-503）
`plan_sync()` 为纯函数三方比对（本地 hash/mtime + 远端 ETag/mtime + sync-state），分支：
仅本地改→上传、仅远端改→下载、双端改→新者为主 + 冲突副本 `<名>-conflict-<ts>.md`、双端同→跳过。
`WebDavClient` 只用 PROPFIND/GET/PUT/MKCOL，Basic auth、HTTPS 检测（HTTP 仅警告）、60s 超时、
412 重比对（由上层重跑）。本地写入全部原子写；与编辑并发时以冲突副本处理，不覆盖缓冲区。
密码经 keyring 存 OS 凭据管理器，`config.json` 仅存 url/username（NFR-108）。

### 3.10 应用基础（M7）
- 配置：`%APPDATA%\MoNote\config.json`，原子保存；损坏时备份 `.bak` 并载入默认（X-13）；
- 通知中心：分级 info/warn/error，最多 100 条，前端常驻入口 + 未读角标；
- 更新检查：7 天节流、自动失败静默、手动失败提示；请求仅含 app/os/ver（NFR-108/AC-035）；
- 快捷键：默认表 + 用户覆盖表，冲突检测返回 1004（FR-606/AC-039）。

## 4. 与设计文档的偏差记录（诚实声明）

| # | 偏差 | 原因 / 影响 |
| --- | --- | --- |
| D-1 | `notes` 表增加 `content` 字段（原始正文缓存），设计 7.2 未列 | 用于检索命中摘要与反链上下文，避免每次查磁盘；属派生数据，可重建，不影响权威副本语义 |
| D-2 | 中文按字检索用"空格分隔 CJK + 短语查询"落地，而非自定义 FTS5 tokenizer | 不引入 SQLite 扩展依赖，行为等价于 DD-4 的按字索引；已在 3.4 说明 |
| D-3 | 启动对账以 mtime 差异为主判据，hash 用于外部改动白名单 | 启动性能优先；内容变更但 mtime 未变的极端场景由 watcher/手动重建兜底 |
| D-4 | watcher 失效时只做启动对账，未实现"30s 轮询"降级 | 本机（本地 NTFS）watcher 可用；网络盘降级为已知限制，后续版本补充轮询 |
| D-5 | 前端预览为整篇重渲染（防抖 150ms），未做"仅重渲染变更段落"的增量渲染 | marked 整篇渲染在 1 万字符笔记内满足 NFR-102 预算（见测试报告冒烟数据）；作为性能优化项记录 |
| D-6 | PDF 导出由前端 `window.print()` 打印管线完成，后端不生成 PDF | 与设计决策 DD-6 一致（避免内置 headless Chromium 导致包体超限）；打印样式已内置 |
| D-7 | WebDAV 未接入真实远端做端到端验证 | 本轮无可用测试服务器；已完成客户端、三方比对纯函数单测与错误路径，真实服务验证列为已知限制 |
| D-8 | 更新检查默认地址 `https://update.monote.app/manifest.json` 为占位服务 | 课程项目无实际更新服务器；地址可在 `config.json` 的 `update.manifestUrl` 修改；失败静默符合 FR-605 |
| D-9 | 跨平台（macOS/Linux）未实测 | 代码使用条件编译与平台目录/凭据抽象，但仅在 Windows 构建验证（FR-601 交付物为 Windows 安装包） |
| D-10 | 应用安装包未在本轮构建（仅 `cargo build/run`） | 安装包需 Tauri CLI 与签名配置；README 已给出 `cargo tauri build` 步骤，源码可直接构建 |
| D-11 | 测试可执行文件额外注入 Common-Controls v6 manifest | `rfd` 原生对话框链接 `comctl32!TaskDialogIndirect`；tauri-build 只给主程序嵌 manifest，测试目标在 `build.rs` 中用 `cargo:rustc-link-arg-tests=/MANIFEST:EMBED` 补齐，否则测试进程启动即 `0xC0000139` |
| D-12 | `config.json` 读取兼容 UTF-8 BOM | Windows 记事本保存的配置常带 BOM；`ConfigStore::load` 先剥离 BOM 再解析，避免误判损坏并回退默认配置 |
| D-13 | 检索摘要从正文生成（剥离 front-matter） | 避免搜索结果摘要出现 `title/tags/created` 等元数据；命中仅在 front-matter（如 tag 过滤）时回退全文开头摘要 |

## 5. 故障模式（X-1~X-14）实现对照

| 故障 | 实现位置 |
| --- | --- |
| X-1 编辑中崩溃/断电 | `vault::write_atomic` + `cleanup_temp_files`；前端 SaveScheduler |
| X-2 索引损坏 | `state::open_vault_internal`（改名重建）+ `rebuild_index` + 降级检索 |
| X-3 库目录只读 | `error::AppError::io`（2002）+ 前端保留缓冲提示 |
| X-4 磁盘不足 | `error::AppError::io` 识别 ERROR_DISK_FULL（2003）+ 备份半成品清理 |
| X-5 断网/同步失败 | `sync::run_sync` 网络错误返回 4003，本地不受影响 |
| X-6 同步冲突 | `sync::plan_sync` + 冲突副本命名 |
| X-7 外部并发改动 | `watcher.rs` + `self_writes` 白名单 |
| X-8 watcher 不可用 | 启动全量对账兜底（轮询降级为已知限制） |
| X-9 文件被占用 | `write_atomic` 重试由前端 30s 重试兜底 |
| X-10 非法/损坏文件导入 | `io::decode_text`/`is_binary` → skipped 报告 |
| X-11 重命名链接断裂 | `state::rename` 调用 `links::rewrite_links` 并重索引 |
| X-12 更新服务故障 | `update::check_update` 自动静默/手动提示 |
| X-13 配置损坏 | `config::ConfigStore::load` → 默认配置 + `.bak` |
| X-14 回收站还原冲突 | `vault::restore_trash` → `-还原-<ts>` |
