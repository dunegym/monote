## 1. 引言

### 1.1 文档目的

本文档定义 MoNote（墨记）v1 版本的功能需求与非功能需求，作为后续设计、开发与测试的依据。文档中的每一项需求均可通过 7.2 节的验收标准进行验证（唯一例外 NFR-110 为过程质量属性，核验方式见 10.2 注）。

**需求与背景的分离约定**：第 2 章为背景信息，仅用于说明"为什么做"；第 4、5 章为正式需求，仅使用"应（shall）"描述"做什么"，不含背景论述。第 9 章的假设不构成需求。

### 1.2 文档范围

本文档覆盖 MoNote v1（桌面端单机版）的需求。云同步服务、移动端、多人协作等明确列入范围外事项（见第 8 章）。

### 1.3 术语与缩略语

| 术语 | 定义 |
| --- | --- |
| 笔记 | 一个以 Markdown 语法编写的 `.md` 纯文本文件及其元数据 |
| 库（Vault） | 用户指定的一个本地文件夹，MoNote 在其中管理全部笔记与附件 |
| 双链 | 形如 `[[目标笔记名]]` 的内部链接语法，指向库内另一篇笔记 |
| 反向链接（反链） | 引用当前笔记的其他笔记的列表 |
| 本地优先 | 数据以本地文件为唯一权威副本，网络功能为可选增强，断网时全部核心功能可用 |
| front-matter | 位于 Markdown 文件开头、以 `---` 包围的 YAML 元数据块 |
| FTS | Full-Text Search，全文检索。本产品技术方案采用 SQLite FTS5 虚拟表模块 |
| P95 | 第 95 百分位数，即 95% 的观测值不超过该指标 |
| WebDAV | 基于 HTTP 的文件访问协议，用于可选的第三方网盘同步 |
| 冷启动 | 操作系统开机后进程首次启动，缓存未预热 |
| 新者为准 | 同步冲突解决策略：保留修改时间较晚的版本 |

### 1.4 文档约定

- 需求编号：功能需求 `FR-<模块号><序号>`，非功能需求 `NFR-<序号>`，场景 `S-<序号>`，验收标准 `AC-<序号>`。
- 优先级定义（与使用频率挂钩）：
  - **高（P0）**：目标用户每次使用几乎必然执行，或缺失则产品不可用；**安全底线类需求（数据不丢失、可恢复、不损坏用户数据）即使执行频率低，也归入高优先级**；
  - **中（P1）**：每周多次使用的功能，缺失明显降低效率，但不阻塞核心流程；
  - **低（P2）**：低频增强功能，可安排在 v1 后期或 v1.1 实现。
- "应"表示强制需求；需求正文不使用"宜"级措辞（v1.0 曾定义"应/宜"两级，因终稿正文无实际"宜"级条目，v1.1 移除该级定义，见《AI 协作记录》R6）。

## 2. 背景与问题陈述

### 2.1 背景描述

学生与知识工作者在日常学习中普遍使用 Markdown 记录课堂笔记、读书笔记与技术文档。现有工具存在三类典型问题：

1. **云端锁定**：主流云笔记服务将数据存储在专有格式或专有云端，导出困难，服务停运即数据丢失风险，且免费额度受限。
2. **知识孤岛**：纯编辑器类工具（如 Typora）只解决"写"，笔记之间缺乏链接组织手段，知识积累为孤立文件，难以复用。
3. **重量级与隐私顾虑**：部分双链工具功能庞大、启动缓慢，或默认强制账号登录，对仅需个人单机使用的用户过重。

### 2.2 问题陈述

目标用户需要一个**数据完全归属本人**（本地纯文本文件）、**支持笔记间双向链接**、**检索快速**、**上手成本低**的轻量桌面工具，解决"记下来 → 找得到 → 连起来 → 带得走"四个环节的问题。

### 2.3 产品定位

MoNote 是一款本地优先的个人 Markdown 笔记与知识管理桌面应用：数据为本地标准 `.md` 文件（可随时用任意编辑器打开，无格式锁定），核心能力为 Markdown 编辑、双链知识组织、快速全文检索、可靠的备份与导出。v1 不提供官方云服务，同步通过用户自有的 WebDAV 网盘可选实现。

## 3. 目标用户与使用场景

### 3.1 目标用户细分

| 编号 | 用户群体 | 特征与诉求 | 对应界面要求（见第 6 章） |
| --- | --- | --- | --- |
| U1 | 大学生/研究生 | 记课堂笔记、整理复习资料；设备性能参差；对费用敏感 | 新手引导、工具栏可见、免费无账号 |
| U2 | 知识工作者（程序员、研究者、写作者） | 长期积累个人知识库，重双链与检索效率，重数据自主权 | 快捷键全覆盖、命令面板、可隐藏工具栏 |
| U3 | 轻度记录者 | 偶尔记录待办与灵感，不使用高级语法 | 默认界面简洁，高级功能不干扰 |

### 3.2 使用场景

| 编号 | 场景名称 | 频率 | 场景描述 |
| --- | --- | --- | --- |
| S-01 | 快速记录 | 高（每日） | 课堂上打开 MoNote，新建笔记，边听边用 Markdown 记录，含代码块与列表；合上电脑时笔记已保存 |
| S-02 | 链接整理 | 高（每日） | 复习时在今日笔记中用 `[[二叉树]]` 引用既有笔记；发现"二叉树"笔记尚不存在则顺手创建；打开"二叉树"笔记查看哪些笔记引用了它 |
| S-03 | 检索回找 | 高（每日） | 考前通过 Ctrl+P 按标题快速打开《操作系统-第3章》，或用全文检索"虚拟内存"找到 3 篇相关笔记并跳转 |
| S-04 | 归类整理 | 中（每周） | 将散落的笔记移动到学期文件夹，给笔记打上 `#考研` 标签，通过标签面板筛选同标签笔记 |
| S-05 | 备份迁移 | 中（每周~每月） | 换新电脑时将整个库文件夹拷贝过去即可继续使用；或配置 WebDAV 在宿舍/实验室两台电脑间同步，冲突时两版都不丢 |
| S-06 | 导出分享 | 中（每周） | 将笔记导出为 PDF 提交给小组；或将整库导出为 HTML 站点发布 |
| S-07 | 异常恢复 | 低（偶发） | 断电或程序崩溃后重新打开，自动恢复到崩溃前数秒内的编辑内容 |
| S-08 | 首次上手 | 一次 | 新用户安装后 10 分钟内完成"创建笔记 → 写 Markdown → 建立第一个双链 → 检索到它"的完整闭环 |

## 4. 功能需求

模块划分：FR-1xx 编辑、FR-2xx 组织、FR-3xx 检索、FR-4xx 导入导出、FR-5xx 备份同步、FR-6xx 应用基础。

### 4.1 编辑模块

**FR-101 Markdown 编辑与实时预览（优先级：高，来源 S-01/S-02）**
- 系统**应**提供左右分栏编辑器：左栏为 Markdown 源文本编辑区，右栏为渲染预览区，预览随输入实时刷新。
- 用户**应**可一键隐藏预览栏或编辑栏（仅剩其一）。
- 输入：键盘输入的 Markdown 源文本（UTF-8）。输出：右栏渲染视图。

**FR-102 Markdown 语法范围（优先级：高，来源 S-01）**
- v1 **应**支持：CommonMark 全部基础语法，以及 GFM 扩展中的表格、任务列表、删除线、围栏代码块（含语言标注与语法高亮）、自动链接。
- 不支持的语法**应**在预览中按纯文本原样显示，不得产生渲染错误或崩溃（错误处理要求）。

**FR-103 图片粘贴与附件管理（优先级：高，来源 S-01/S-06）**
- 用户在编辑器中粘贴剪贴板图片时，系统**应**自动将图片保存至库内 `attachments/` 目录（文件名为 `IMG-<时间戳>.<扩展名>`），并在光标处插入相对路径的 Markdown 图片链接。
- 支持 PNG/JPEG/WebP/GIF 格式；单张超过 10 MB 时**应**拒绝粘贴并弹出提示"图片超过 10 MB 限制"。
- 异常处理：库目录只读导致保存失败时，**应**弹出错误提示且不插入失效链接。

**FR-104 格式工具栏（优先级：中，来源 S-01/S-08）**
- 编辑器**应**提供工具栏按钮完成加粗、斜体、标题（H1–H3）、无序/有序列表、引用、行内代码、代码块、链接、表格的语法插入。
- 用户**应**可隐藏工具栏（见 6.2）。

**FR-105 自动保存（优先级：高，来源 S-01/S-07）**
- 编辑停顿 2 秒、切换笔记、窗口失焦、退出程序四个事件之一发生时，系统**应**将当前内容写入磁盘。
- 系统不应提供"手动保存"作为唯一保存方式（手动 Ctrl+S 快捷键仍应保留）。

**FR-106 数学公式渲染（优先级：低，来源 3.1 U2，画像推断）**
- 预览**应**支持 KaTeX 语法的行内公式（`$...$`）与块级公式（`$$...$$`）渲染。
- 语法错误时**应**在原位置以红色文字显示错误信息，不得静默失败。

**FR-107 大纲导航（优先级：中，来源 S-03）**
- 预览栏**应**提供基于标题层级（H1–H3）的大纲面板，点击大纲项滚动至对应位置；编辑长文时大纲随内容同步刷新。

### 4.2 组织模块

**FR-201 文件夹管理（优先级：高，来源 S-04）**
- 用户**应**能在库内创建、重命名、移动、删除文件夹，层级不限。
- 重命名文件夹时，系统**应**自动更新库内指向该文件夹内笔记的所有相对链接。
- 删除非空文件夹**应**弹出确认对话框，删除内容移入回收站（FR-205）。

**FR-202 标签（优先级：高，来源 S-04）**
- 系统应支持两种打标方式：在正文中使用 `#标签名` 行内语法；或在笔记属性面板添加标签（写入 front-matter 的 `tags` 字段）。两种方式等价，标签面板中合并计数。
- 侧边栏**应**提供标签面板，显示全部标签及笔记数量，点击筛选出对应笔记列表。
- 标签名**应**支持中文、字母、数字与连字符，不支持空格（以空格分隔多个行内标签）。

**FR-203 双向链接（优先级：高，来源 S-02）**
- 在编辑器输入 `[[` 时，系统**应**弹出笔记名自动补全列表（按修改时间排序，至多 10 项，支持继续输入过滤）。
- 链接目标不存在时，系统**应在**预览中以特殊样式显示该链接，点击后创建同名空白笔记并跳转。
- 支持 `[[目标笔记名|显示文字]]` 别名语法。
- 输入输出格式见附录 A.3。

**FR-204 反向链接面板（优先级：高，来源 S-02）**
- 每篇笔记**应**提供反链面板，列出所有引用当前笔记的笔记，每条显示引用处上下文（引用语句前后各至多 80 字符）。
- 点击反链条目**应**跳转至源笔记并高亮引用位置。
- 引用当前笔记的链接被删除或目标被重命名后，反链面板**应**在 2 秒内随之更新，无需重启（见 AC-011）。
- 链接目标笔记被删除时，各处指向它的双链**应**显示为"缺失链接"占位样式，点击时提示"目标笔记不存在，是否重建？"，不产生跳转错误。

**FR-205 回收站（优先级：高，来源 S-04/S-07）**
- 删除笔记/文件夹**应**移入库内 `.trash/` 目录（回收站），回收站内笔记可一键还原至原路径。
- 回收站中的项目**应**在进入回收站满 30 天后于程序启动时自动永久清除（时间相关需求）；清除前 7 天内在回收站面板显示倒计时提示。
- 异常处理：还原时原路径已存在同名文件，则自动重命名为 `<原名>-还原-<时间戳>`。

### 4.3 检索模块

**FR-301 标题快速打开（优先级：高，来源 S-03）**
- 全局快捷键 Ctrl+P **应**唤起标题检索框：按笔记名模糊匹配，默认按最近打开时间排序，回车打开选中项，支持方向键选择。

**FR-302 全文检索（优先级：高，来源 S-03）**
- Ctrl+Shift+F **应**唤起全文检索面板：在全部笔记正文与标题中检索关键词，结果列表显示笔记名、命中行摘要（命中词高亮）、最后修改时间。
- 检索语法**应**支持：多关键词 AND（空格分隔）、精确短语（英文双引号包裹）、`tag:标签名` 过滤。
- 结果**应**支持按相关度（默认）与修改时间两种排序切换。
- 后台索引异常损坏时，系统**应**自动降级为逐文件扫描并提示"正在重建索引"，期间检索功能保持可用，不得中断服务（异常处理）。

**FR-303 检索范围过滤（优先级：中，来源 S-04）**
- 检索面板**应**支持按文件夹、标签、修改时间区间（今天/最近 7 天/最近 30 天/自定义）过滤结果。

### 4.4 导入导出模块

**FR-401 导入（优先级：高，来源 S-05）**
- 系统**应**支持导入单个 `.md`/`.markdown` 文件及整个文件夹（保留子目录结构）。
- 异常处理：非 UTF-8 编码文件，系统**应**尝试以 GB18030 转码导入并标记提示；二进制或损坏文件**应**跳过并在导入完成报告中列出文件名与原因。

**FR-402 单篇导出（优先级：高，来源 S-06）**
- 单篇笔记**应**可导出为：Markdown（.md）、HTML（内联样式的单文件）、PDF（默认 A4）。
- 导出 HTML/PDF 时**应**将本地图片一并嵌入（HTML 为 base64 内联，PDF 直接渲染）。

**FR-403 整库导出（优先级：中，来源 S-05/S-06）**
- 系统**应**支持将整库导出为一个 ZIP 压缩包，保持目录结构、相对链接与附件的对应关系，解压后可被 MoNote 直接作为新库打开。

### 4.5 备份与同步模块

**FR-501 本地存储（优先级：高，来源全部场景）**
- 全部笔记**应**以标准 UTF-8 `.md` 纯文本文件存储于用户指定的库文件夹中，元数据使用 YAML front-matter（见附录 A），不引入任何专有数据库格式作为唯一数据副本。
- 卸载程序后，库文件夹中的数据**应**保持完整可用。

**FR-502 自动备份（优先级：高，来源 S-05/S-07）**
- 每次程序启动时，若距上次备份超过 24 小时，系统**应**自动将整库打包备份至用户指定的备份目录（默认：系统文档目录下 `MoNote-Backup/`）。
- 备份文件命名：`monote-backup-YYYYMMDD-HHmmss.zip`。
- 系统**应**仅保留最近 5 份备份，超出时删除最旧备份；备份失败（磁盘不足等）**应**在界面通知中心提示且不影响主功能。
- 用户**应**可随时手动触发"立即备份"。

**FR-503 WebDAV 同步（优先级：中，来源 S-05）**
- 用户**应**可配置一个 WebDAV 服务器（地址、账号、密码）用于整库同步，可设为手动触发或启动时自动同步。
- 同步冲突处理策略**应**为"新者为准 + 冲突副本"：修改时间较新的版本作为主版本，较旧版本保留为同名冲突副本文件 `<笔记名>-conflict-<时间戳>.md`，不静默丢弃任何一版。
- 密码凭据**应**存储于操作系统凭据管理器（Windows Credential Manager / macOS Keychain），不得明文写入配置文件（安全要求，见 NFR-108）。
- 同步过程中断网：**应**终止本次同步并提示，本地数据不受影响。

### 4.6 应用基础模块

**FR-601 跨平台分发（优先级：高，来源 S-08）**
- 系统**应**提供 Windows 10+（x64）、macOS 12+（Intel 与 Apple Silicon）、Ubuntu 22.04 LTS（及内核兼容的主流发行版）安装包。

**FR-602 主题（优先级：中，来源 3.1 U1/U3）**
- 系统**应**内置亮色与暗色两套主题，跟随系统外观自动切换，也支持手动指定。

**FR-603 界面语言（优先级：低，来源 3.1 U2）**
- v1 **应**内置简体中文界面；界面文案集中于语言资源文件统一管理，以便后续扩展英文。
- 其他语言界面不纳入 v1 范围（v1.1 候选）；简体中文界面的完整性按 AC-034 验收。

**FR-604 命令面板（优先级：中，来源 3.1 U2）**
- Ctrl+Shift+P **应**唤起命令面板，模糊搜索并执行全部可用命令（新建笔记、导出、切换主题等），键盘全程可操作。

**FR-605 版本更新检查（优先级：低，来源 9.1 网络环境假设）**
- 系统**应**默认每 7 天执行一次版本更新检查，仅向官方更新服务器发送当前版本号与操作系统类型，不上传任何笔记内容（与 NFR-108 口径一致）。
- 用户**应**可在设置中关闭自动检查，或手动触发"检查更新"。
- 异常处理：检查失败（含断网）时**应**静默跳过且不影响任何功能；手动触发失败时**应**提示"检查失败，请检查网络后重试"。
- v1 仅提示新版本，不自动下载安装。

## 6. 界面与交互需求

### 6.1 总体布局

主界面为三栏布局：左侧边栏（文件夹树、标签面板、检索入口）、中间编辑区、右侧预览区。各栏均**应**可折叠。底部状态栏显示当前笔记字数、保存状态与同步状态。

### 6.2 面向不同用户界面的差异化要求

| 用户 | 界面要求 |
| --- | --- |
| 新手（U1/U3） | 首次启动显示 3 步引导（新建笔记 → 双链 → 检索）；FR-104 工具栏默认可见；不显示任何需要配置的功能入口（WebDAV 等收纳于设置） |
| 高级用户（U2） | 支持隐藏工具栏与侧边栏（快捷键 Ctrl+\）；FR-604 命令面板覆盖全部命令；全部功能有可自定义快捷键 |
| 键盘/无障碍用户 | 全部功能键盘可达（含 NFR-111）；焦点顺序符合视觉顺序；交互控件有可访问名称（ARIA） |

### 6.3 关键交互约束

- 破坏性操作（删除非空文件夹、清空回收站、覆盖式还原）**应**弹出确认对话框，且确认按钮不得是默认焦点。
- 所有后台任务（索引重建、备份、同步）**应**在状态栏显示进度，不阻塞编辑。

## 7. 验收标准

### 7.1 验收环境与方法约定

- 基准环境：Intel i5 四核 / 8 GB 内存 / SSD / 1080p 显示屏（9.1）。
- 基准数据集：由脚本生成的 10,000 篇笔记（平均 1 KB，含标题/正文/标签/双链）。
- 性能测试方法：每项操作连续执行 50 次取 P95；冷启动测 5 次取中位数。

**关键非功能指标度量方法**（补齐 NFR-102/109/110 的度量口径，与 AC-025/032/036 配套）：

| 指标 | 度量方法 | 采样与判定门限 |
| --- | --- | --- |
| NFR-102 按键回显延迟 | 自动化输入脚本逐次派发单字符按键，在编辑器输入事件处理器与预览字符上屏处分别打点，取两打点差值；排除输入法组合窗口期间的样本 | 1,000 次按键，P95 ≤ 50 ms |
| NFR-102 预览渲染刷新 | 同上脚本，测量输入事件至预览区对应 DOM 节点变更完成的耗时 | P95 ≤ 200 ms |
| NFR-109 内存占用 | 操作系统任务管理器（或 `ps`/性能计数器）读取进程工作集，空闲 10 分钟后每 30 秒采样 1 次、共 5 次 | 中位数 ≤ 300 MB |
| NFR-109 安装包体积 | 读取安装程序文件属性大小 | ≤ 150 MB |
| NFR-110 覆盖率 | 测试框架行覆盖率报告（如 vitest + c8），仅统计编辑器与索引模块源码目录 | ≥ 70% |
| NFR-110 模块解耦 | 依赖检查脚本（如 dependency-cruiser）声明编辑器/索引/同步三模块边界规则并在 CI 执行 | 越界引用 0 处 |

## 9. 假设、依赖与约束

### 9.1 基准环境假设

- 用户设备：2018 年后主流个人电脑（四核 CPU、8 GB 内存、SSD、1080p 及以上）。
- 网络环境：WebDAV 同步与版本更新检查（FR-605）时可联网；断网时除同步外全部功能可用。

### 9.2 技术依赖

| 依赖 | 用途 | 说明 |
| --- | --- | --- |
| Tauri 2（或 Electron） | 跨平台桌面壳 | 二选一，选型时以 NFR-109 体积/内存指标为决策依据 |
| SQLite + FTS5 | 全文检索索引 | 索引为派生数据，可随时由 .md 文件重建，不构成格式锁定 |
| KaTeX | 公式渲染（FR-106） | MIT 开源 |
| 用户自备 WebDAV 服务 | 同步（FR-503） | 如坚果云等；MoNote 不提供服务器端 |

### 9.3 兼容性约束（对应 NFR-107）

Windows 10 及以上（x64）；macOS 12 Monterey 及以上（x64 + Apple Silicon）；Ubuntu 22.04 LTS 及兼容内核的主流 Linux 发行版。

### 9.4 关键假设

- A-1：目标用户可接受"无官方云同步"，其同步需求可由自有 WebDAV 满足（依据：3.1 目标用户定位与 2.1 问题 1/3）。
- A-2：10,000 篇 / 2 GB 已覆盖个人 5 年以上的笔记积累规模（依据：个人知识库行业经验值，见人工核实说明 V-4）。
- A-3：本地 `.md` + YAML front-matter 的存储方案能满足"无格式锁定"诉求（依据：同类产品 Obsidian 采用同样方案的公开事实，见人工核实说明 V-1）。

## 附录 A：数据格式细则

### A.1 笔记文件

- 扩展名：`.md`（导入兼容 `.markdown`）；编码：UTF-8 无 BOM；换行符：LF（导入 CRLF 时自动转换）。

### A.2 front-matter 元数据

```yaml
---
title: 操作系统-第3章        # 缺省时取文件名
tags: [考研, 操作系统]
created: 2026-09-18T10:30:00+08:00   # ISO 8601，含时区
updated: 2026-09-18T21:05:12+08:00
---
```

`created`/`updated` 由系统维护；用户手改后以用户值为准。

### A.3 双链语法

| 语法 | 含义 |
| --- | --- |
| `[[目标笔记名]]` | 链接到库内文件名为 `目标笔记名` 的笔记 |
| `[[目标笔记名|显示文字]]` | 同上，显示为自定义文字 |
| `[[#标题名]]` | 链接到当前笔记内的标题（v1 支持） |

链接解析以**文件名（去扩展名）**为目标，同一库内文件名应唯一；重名时以路径更浅者优先并在补全列表中显示路径消歧。

### A.4 库目录结构（约定）

```
Vault/
├── *.md                # 笔记（子目录层级不限）
├── attachments/        # 图片等附件（FR-103）
├── .trash/             # 回收站（FR-205）
└── .monote/            # 应用私有目录：检索索引、配置缓存（均为可重建的派生数据，删除不影响笔记数据）
```

### A.5 备份包结构

`monote-backup-YYYYMMDD-HHmmss.zip` 内容即库目录全量快照（含 `.trash`，不含 `.monote` 索引缓存）。
